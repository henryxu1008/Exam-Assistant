# 学习存储 AI 分段与单项预算：合成对比（2026-11-02）

- 执行：`node scripts/benchmark-learning-storage.js --sizes 1000,10000 --runs 5`。
- 环境：v24.22.1 / linux x64；每样本独立进程、每场景 5 次。
- 全量回归结束后单独运行本轮基准；无云、无真实文件输入、无付费 AI。
- 运行真实 store.load / 创建会话 / 首次迁移 / submitAttempt；只测云端 ACK 前的一次本地作答。
- 历史参考为上一份分段报告（PR #18），不是同一次 A/B 测量；精确计数、原始样本和本轮源文件 SHA-256 见同名 JSON。

| 已有作答 | AI 消息 | 原分段活动根 B | 本轮活动根 B | 本轮作答页写入 | 本轮 AI 页写入 | 本轮本地提交 p50 ms |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 0 | 8,886 | 8,886 | 0 | 0 | 10.84 |
| 1,000 | 1,000 | 506,275 | 11,708 | 0 | 0 | 13.15 |
| 10,000 | 0 | 33,355 | 33,355 | 0 | 0 | 60.75 |
| 10,000 | 10,000 | 5,017,244 | 60,626 | 0 | 0 | 91.32 |

1 万作答 + 1 万 AI 消息的活动根由 5,017,244 B 降至 60,626 B，写入量减少约 98.79%。
每场景只有一次根写入，作答页和 AI 页均未重写。导出验证全部事实、AI 条数和新待传项仍齐全。
本轮 Node CPU 耗时不支持宣称较上轮更快；减少的是根序列化和原生写入的数据量，微信桥接/磁盘收益尚未测量。

分块备份和校验有显著成本：1 万 + 1 万压力场景首次迁移约 11.98 秒，总本地约 37.52 MB。
heap 是提交后一次观测的最大值，不是峰值或强制 GC 后的存活内存；受未回收临时对象、V8 和进程采样影响。
首次迁移的同步等待、内存和额外空间仍是阻塞发布的验收项，不将写入减少解释为总容量或 CPU 成本降低。

## 原生限制与验收边界

- 适配器显式给出 1 GiB 合成额度；直接播种的大旧快照可能超出原生单 key 和总额度。
- 因此 1 万条压力场景不证明能放入微信。真实 10 MB 等额度必须由运行时返回，空间不足明确失败或在完整旧格式可保存时延期。
- 本轮所有新写入都经过 900 KiB（含 key 的 UTF-8 JSON 估算）预算；单条消息、活动根或旧格式回滚仍可能被拒绝。
- 初始种子不是通过原生 API 写入，不能把合成读入大旧档案算作已完成真实迁移。
- 云同步仍发送完整领域数据，未优化服务端 AI 文档体积、网络和待传历史。
- 故障回归共 84 个 API 边界进程退出点，包含 AI 和分块备份；不代表原生半写、断电或介质故障已验收。
- 微信开发者工具/隔离设备的配额、界面、等待、恢复与回滚验收仍未完成。
