# ADR 0009：同步提交、清空代次与共享资源权限

- 状态：Accepted（PR #10 代码；尚未部署）
- 关联：Issue #3、#5、#7、#8、#11
- 决策：在现有云开发后端内补齐一致性与权限边界，后续再实施 ADR 0007 的事件同步协议。

## 已复现的根因

原 studySync 在档案事务提交后才写流水。暂停流水写入时，另一个设备可读到已提交标记但没有答案；流水写失败也不能回滚档案。删除只按客户端队列排序，另一设备上传清空前的快照仍能让数据复活。bankSync 允许普通用户首次初始化共享题库；aiTutor 只有全局预算，没有业务身份与每用户预算。

故障测试使用真实入口和内存数据库/传输替身，不访问真实学习数据。原实现回放新增的 7 个针对性测试均失败，修复后通过。另有真实 store + studySync 的双设备组合测试。

## 同步契约

| 字段 | 所有者与语义 |
| --- | --- |
| `dataEpoch` | 服务端账号清空代次；旧文档视为 0。客户端只能携带，不能通过 stats 修改 |
| `syncRevision` | 每次成功更新或清空时递增，保证恢复分页来自同一修订 |
| `deleteId` | 客户端清空操作 ID，按账号持久化，在网络重试/重启后复用 |
| `lastDeleteId` | 服务端最后接受的清空 ID，后续普通更新保留 |

`update` 在一个事务内读取账号档案，校验 dataEpoch，读取/写入流水并写档案。已接受的流水按 `(openid, dataEpoch, attempt.id)` 幂等，同 ID 不同内容返回 `ATTEMPT_CONFLICT`，整批回滚。流水清洗失败不再静默跳过。

事务最多处理 48 条流水，最多 98 次文档操作（档案读写 2 次，流水各读写 2 次）。[CloudBase 事务文档](https://docs.cloudbase.net/database/transaction)规定最多 100 次操作、30 秒、仅支持 doc 操作，不能在事务中使用 where。客户端分批只上传流水，最后一批才附完整档案；后续 [ADR 0010](0010-durable-attempt-outbox.md) 改为按 ID 持久确认每批进度，失败保留剩余 outbox。上传档案在入队时深拷贝，后续作答不能混入已捕获的请求。

`get` 读取档案修订、查询一页流水、再读修订；中间有提交则返回 `SNAPSHOT_CHANGED`。后续页带第一页面的 dataEpoch 和 syncRevision。任一页失败或修订变化，客户端整批丢弃，不发布档案、答案或完成状态；下次恢复从第一页重试。清空后的查询只读当前代次。

```json
{"action":"update","token":"<session>","dataEpoch":1,"attempts":[],"stats":{"version":3,"records":{}}}
```

```json
{"action":"get","token":"<session>","skip":100,"dataEpoch":1,"syncRevision":23}
```

## 清空契约

1. 客户端保留已知 dataEpoch，先按真实账号作用域持久化 deleteId 和待删除标记，不依赖云初始化成功或当前令牌可用。匿名清空仅影响本地；发送时仍须云就绪、有效会话和同一账号作用域。恢复连接/重启时删除优先于启动拉取标记，先补删除，再放行恢复和清空后的新数据上传（评审 r4432439632）。
2. 服务端事务发布不含学习内容的墓碑并递增 dataEpoch，立即阻断旧上传。
3. 事务外分页清理旧代次及无代次的历史流水。新代次文档 ID 使用账号/代次/逻辑 ID 的 SHA-256，和历史 `openid__id` 命名空间不相交，清理不会删到新流水。
4. 物理清理失败返回 `DELETE_ATTEMPTS_FAILED`；墓碑仍有效，同 ID 重试继续清理，不能提前清除客户端标记。
5. 同 deleteId 重试不再次递增代次。旧设备的其他清空请求如果已被新清空取代，返回 `superseded:true`；客户端丢弃尚未获新代次的本地学习数据并恢复当前云端，不能把它带入新代次。
6. 其他设备收到 `STALE_EPOCH` 或恢复发现更高代次，作废旧学习数据、待传队列和页面/异步上下文，恢复当前代次。旧代次离线作答不自动跨清空边界合并。

```json
{"action":"delete","token":"<session>","dataEpoch":0,"deleteId":"reset_<persistent-id>"}
```

本地清空的提交点是删除意图成功写盘（评审 r4434188501）。`clearAll()` 先持久化操作，失败返回 `{ok:false,error:"PERSIST_DELETE_FAILED"}`，保留原档案、待传进度及页面上下文，不发送删除或空快照；个人页提示失败，不显示清空成功。

每次显式本地清空同时生成 `localResetId`，清空快照用 `pendingDeleteId` 与其关联。若意图已提交但清空快照未落盘就退出，重新加载时重建空快照，避免旧数据被上传到新代次；云端重试仍复用原 `deleteId`。旧布尔标记迁移保留原有清空后本地数据。服务端确认后先同步落盘新 dataEpoch 和本地数据，再移除待删除标记；任一步失败都保留同一操作重试。标记读取失败阻止恢复与上传，后台重试不会把一次读失败误当成新删除请求；恢复读取后补传本地待同步数据。已采用的新代次不会因确认标记移除失败而再次丢弃新作答。

墓碑是防复活的必要元数据，不应被普通清理任务删除。这里的操作是清空学习档案，不是删除 users 账号。

## AI 对话独立清空（评审 r4432365981）

两台设备从本地 aiEpoch=0 分别清空都会得到 1，后一次空列表会和前一次清空后的消息合并。版本不能由各设备独立加一，或由设备时钟推断全局先后。

- 新增 `studySync action=clearAI`，携带当前 dataEpoch 和持久 clearId。服务端事务递增账号 aiEpoch，清空 aiMessages 并推进 syncRevision；不同清空按事务提交顺序排序，不依赖客户端时钟或已缓存的 aiEpoch。
- 同一事务在现有 studyStats 集合写 `aiClear_<SHA-256(openid, dataEpoch, clearId)>` 回执文档（kind=aiClearReceipt），只含归属/代次/时间元数据，不含消息。一个清空最多 4 次文档操作。回执读写失败整个事务回滚；缺失与数据库访问失败仍严格区分。
- 回执用于区分独立清空和重试。A 的回包丢失、B 再清空并发送新消息后，A 重试只返回当前代次及 superseded，不再次递增或清空。回执不能单独过期删除；整体 dataEpoch 清空会一并清理旧代次回执，此后旧操作会被 dataEpoch 拒绝。日常按用户读取仍只读 studyStats/<openid>。
- 客户端本地立即清空并失效旧页面/模型回复；按账号把每次操作写入本地档案的 aiClearQueue，确认操作 ID 已落盘才发送。连续清空分别排队，重启/失败复用原 ID，不将每次重试当作独立清空。写盘失败保留待写状态，不发送不可恢复的清空操作。
- AI 清空待确认时保留后续消息与学习数据在本地，暂缓快照上传和恢复，直到队列确认；离线仍可练习。被其他清空取代的未确认对话不跨代次上传。切账号、整体清空和清空前发出的旧恢复回包不得污染当前档案。
- 普通 update 不得生成 aiEpoch。旧/自造 AI 代次只丢弃 AI 片段，仍原子提交本次学习档案与作答，并返回 aiStale/当前 aiEpoch；客户端随后恢复当前对话。get 始终单独返回服务端 aiEpoch，包括学习档案墓碑场景。相同服务端代次内继续合并正常消息。

```json
{"action":"clearAI","token":"<session>","dataEpoch":0,"clearId":"ai_clear_<persistent-id>"}
```

此协议需客户端与服务端协调升级。旧客户端通过本地 aiEpoch+1 上传空列表不再是有效清空操作，不能作为兼容路径保留；上线前通过版本更新机制要求升级。未对真实数据库、索引或权限执行变更。

## 共享资源权限

- 题库初次导入和强制覆盖都必须是服务端管理员（ADMIN_OPENIDS / appConfig.admins 或管理员密钥）；覆盖仍要求 force=true。普通启动不再自动播种题库。读取失败不能触发导入；管理员密钥不得放入小程序。
- AI 云函数验证有效业务 token，账号取自服务端 users。鉴权不可用、配额存储不可用、事务不可用都回落本地，不调用付费上游。
- 每用户每日上限 `AI_TUTOR_USER_DAILY_CAP` 默认 20，必须为正安全整数；全局 `AI_TUTOR_DAILY_CAP` 默认 200，非负安全整数，只有显式 0 表示无全局限制。两份配额在同一事务共同预约；拒绝不扣减另一份额度。上游失败仍计入预约，避免失败请求绕过成本限制。
- 迁移保留旧每日总计数，旧版随机 ID 计数只汇总一次，不把新用户分区重复计入。新增 auth/db-error 部署副本纳入 CI 一致性校验。

## 发布与回滚约束（供运维审阅，本次不执行）

- 先在独立测试环境验证 SDK 事务回滚/冲突重试及所需索引；现有自动测试使用替身，不能替代云端验收。
- studySync 的客户端和服务端必须协调发布。旧客户端单批超过 48 条会收到 BATCH_TOO_LARGE；没有 deleteId 的旧清空会收到 RESET_PROTOCOL_REQUIRED；清空后无代次的旧上传会收到 STALE_EPOCH。通过已存在的强制更新机制要求升级，不能为了兼容旧端放松代次校验。
- 旧数据无需批量改写，按代次 0 读取。保留 `studyStats` 墓碑与现有旧集合；任何回滚都必须保留新服务端的代次、原子提交和权限校验，不可直接退回无代次后端。
- 云端集合至少包括 users、studyStats、attempts、questions、appConfig；启用 AI 时另需 aiTutorUsage。检查 users.token / openid 查询索引，以及 attempts 的 openid、dataEpoch、createdAt、_id 分页/清理查询索引；studyStats 的 kind、openid、dataEpoch 用于旧清空回执的清理索引。限制数据库客户端直写，身份和共享配置只经服务端校验。该权限配置尚未访问或变更。
- 检查固定 `_id` 写入与运行时安全配置，包括 aiTutorUsage 的每日和用户计数器；不要向客户端暴露运营或上游密钥。
- 大量历史的物理清理可能跨请求超时，客户端必须保持同一 deleteId 重试；未清理完不能宣称已物理删除。后续可将清理任务持久化为后台作业，但代次边界必须同步生效。
