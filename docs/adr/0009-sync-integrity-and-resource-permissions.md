# ADR 0009：同步提交、清空代次与共享资源权限

- 状态：Accepted（PR #10 代码；尚未部署）
- 关联：Issue #3、#5、#7、#8、#11
- 决策：在现有云开发后端内补齐一致性与权限边界，后续再实施 ADR 0007 的事件同步协议。

## 已复现的根因

原 studySync 在档案事务提交后才写流水。暂停流水写入时，另一个设备可读到已提交标记但没有答案；流水写失败也不能回滚档案。删除只按客户端队列排序，另一设备上传清空前的快照仍能让数据复活。bankSync 允许普通用户首次初始化共享题库；aiTutor 只有全局预算，没有业务身份与每用户预算。

故障测试使用真实入口和内存数据库/传输替身，不访问真实学习数据。原实现回放新增的 7 个针对性测试均失败，修复后通过。另有真实 store + studySync 的双设备组合测试。

## 同步契约

| 字段 | 所有者与语义 |
| --- | --- |
| `dataEpoch` | 服务端账号清空代次；旧文档视为 0。客户端只能携带，不能通过 stats 修改 |
| `syncRevision` | 每次成功更新或清空时递增，保证恢复分页来自同一修订 |
| `deleteId` | 客户端清空操作 ID，按账号持久化，在网络重试/重启后复用 |
| `lastDeleteId` | 服务端最后接受的清空 ID，后续普通更新保留 |

`update` 在一个事务内读取账号档案，校验 dataEpoch，读取/写入流水并写档案。已接受的流水按 `(openid, dataEpoch, attempt.id)` 幂等，同 ID 不同内容返回 `ATTEMPT_CONFLICT`，整批回滚。流水清洗失败不再静默跳过。

事务最多处理 48 条流水，最多 98 次文档操作（档案读写 2 次，流水各读写 2 次）。[CloudBase 事务文档](https://docs.cloudbase.net/database/transaction)规定最多 100 次操作、30 秒、仅支持 doc 操作，不能在事务中使用 where。客户端分批只上传流水，最后一批才附完整档案；全部确认前不推进本地总游标。上传档案在入队时深拷贝，后续作答不能混入已捕获的请求。

`get` 读取档案修订、查询一页流水、再读修订；中间有提交则返回 `SNAPSHOT_CHANGED`。后续页带第一页面的 dataEpoch 和 syncRevision。任一页失败或修订变化，客户端整批丢弃，不发布档案、答案或完成状态；下次恢复从第一页重试。清空后的查询只读当前代次。

```json
{"action":"update","token":"<session>","dataEpoch":1,"attempts":[],"stats":{"version":3,"records":{}}}
```

```json
{"action":"get","token":"<session>","skip":100,"dataEpoch":1,"syncRevision":23}
```

## 清空契约

1. 客户端保留已知 dataEpoch，持久化 deleteId 和待删除标记；确认前阻止上传和恢复。
2. 服务端事务发布不含学习内容的墓碑并递增 dataEpoch，立即阻断旧上传。
3. 事务外分页清理旧代次及无代次的历史流水。新代次文档 ID 使用账号/代次/逻辑 ID 的 SHA-256，和历史 `openid__id` 命名空间不相交，清理不会删到新流水。
4. 物理清理失败返回 `DELETE_ATTEMPTS_FAILED`；墓碑仍有效，同 ID 重试继续清理，不能提前清除客户端标记。
5. 同 deleteId 重试不再次递增代次。旧设备的其他清空请求如果已被新清空取代，返回 `superseded:true`；客户端丢弃尚未获新代次的本地学习数据并恢复当前云端，不能把它带入新代次。
6. 其他设备收到 `STALE_EPOCH` 或恢复发现更高代次，作废旧学习数据、游标和页面/异步上下文，恢复当前代次。旧代次离线作答不自动跨清空边界合并。

```json
{"action":"delete","token":"<session>","dataEpoch":0,"deleteId":"reset_<persistent-id>"}
```

墓碑是防复活的必要元数据，不应被普通清理任务删除。这里的操作是清空学习档案，不是删除 users 账号。

## 共享资源权限

- 题库初次导入和强制覆盖都必须是服务端管理员（ADMIN_OPENIDS / appConfig.admins 或管理员密钥）；覆盖仍要求 force=true。普通启动不再自动播种题库。读取失败不能触发导入；管理员密钥不得放入小程序。
- AI 云函数验证有效业务 token，账号取自服务端 users。鉴权不可用、配额存储不可用、事务不可用都回落本地，不调用付费上游。
- 每用户每日上限 `AI_TUTOR_USER_DAILY_CAP` 默认 20，必须为正安全整数；全局 `AI_TUTOR_DAILY_CAP` 默认 200，非负安全整数，只有显式 0 表示无全局限制。两份配额在同一事务共同预约；拒绝不扣减另一份额度。上游失败仍计入预约，避免失败请求绕过成本限制。
- 迁移保留旧每日总计数，旧版随机 ID 计数只汇总一次，不把新用户分区重复计入。新增 auth/db-error 部署副本纳入 CI 一致性校验。

## 发布与回滚约束（供运维审阅，本次不执行）

- 先在独立测试环境验证 SDK 事务回滚/冲突重试及所需索引；现有自动测试使用替身，不能替代云端验收。
- studySync 的客户端和服务端必须协调发布。旧客户端单批超过 48 条会收到 BATCH_TOO_LARGE；没有 deleteId 的旧清空会收到 RESET_PROTOCOL_REQUIRED；清空后无代次的旧上传会收到 STALE_EPOCH。通过已存在的强制更新机制要求升级，不能为了兼容旧端放松代次校验。
- 旧数据无需批量改写，按代次 0 读取。保留 `studyStats` 墓碑与现有旧集合；任何回滚都必须保留新服务端的代次、原子提交和权限校验，不可直接退回无代次后端。
- 云端集合至少包括 users、studyStats、attempts、questions、appConfig；启用 AI 时另需 aiTutorUsage。检查 users.token / openid 查询索引，以及 attempts 的 openid、dataEpoch、createdAt、_id 分页/清理查询索引。限制数据库客户端直写，身份和共享配置只经服务端校验。该权限配置尚未访问或变更。
- 检查固定 `_id` 写入与运行时安全配置，包括 aiTutorUsage 的每日和用户计数器；不要向客户端暴露运营或上游密钥。
- 大量历史的物理清理可能跨请求超时，客户端必须保持同一 deleteId 重试；未清理完不能宣称已物理删除。后续可将清理任务持久化为后台作业，但代次边界必须同步生效。
