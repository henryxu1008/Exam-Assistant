# ADR 0015：用户隔离仓储与已确认作答分段（Issue #11 第一阶段）

- 状态：Implemented，未部署；微信设备容量/中断行为未验收
- 前置：ADR 0010–0013 的持久 outbox、显式事务确认、代次和原题证据
- 应用代码版本：1.1.0；学习领域快照仍为 v3，云端同步协议不变

## 问题与边界

原 store 每次作答序列化并写入全部历史。合成基线中 1 万条已确认流水每次写约 12.87 MB。
本阶段把本地存取集中到 utils/local-repository.js，将已确认不可变流水分段，保留 store 对外领域 API。
AI 历史、聚合、设置、会话和待传队列仍在活动检查点；本次不同时拆全部领域或修改云函数。

## 物理格式与读取

| 数据 | key / 格式 | 权威与保留 |
| --- | --- | --- |
| 活动检查点 | 原账号 key `exam_quiz_data_v1__<scope>`；物理 version:4、localRepository.version:1 | 保存聚合、设置、会话、AI、待传事实/outbox 和历史描述符 |
| 已确认历史 | `exam_quiz_history_v1__<scope摘要>__<内容摘要>` | 不可变；内容绑定 scope 摘要、dataEpoch、pendingDeleteId 与完整原题事实 |
| 首次迁移备份 | `exam_quiz_backup_v1__<scope摘要>` | 原始完整旧快照；不自动作为最新状态恢复，不是后续操作的权威 |
| 作用域删除墓碑 | 原账号 key 中的空 version:4 检查点 | 先提交逻辑删除，再清理分段与备份，清理失败不能复活旧数据 |

仅当 outbox 已有明确队列且事实 ID 不在待传项中，才将事实放入历史。无 outbox 的旧流水仍按现有规则
安全入队，不能凭“历史存在”认定已确认。服务端恢复的规范 ID 与原待传操作可共存，恢复证据不直接出队。
历史引用包含 count/hash；冷读校验作用域、代次、内容摘要、ID 唯一性及待传证据，失败抛出明确错误。
热缓存复用只读事实，并检查所引用 key 仍存在；切账号释放历史缓存，下次重新校验内容。

read/export 重建完整领域 v3 快照，物理元数据不进入云端 payload。历史通过块与活动流水重建，业务仍按稳定
ID 查找，不依赖物理数组顺序。旧检查点读取兼容；未知新格式、缺失/损坏分段或访问失败不能回落成空账号。
store.load 保留错误并阻止后续写入/同步覆盖，不用旧备份冒充完整恢复。

## 写入顺序和首次迁移退路

1. 校验候选快照、outbox 和全部事实身份；复用仍有效的历史页。
2. 初次分段前备份旧完整快照；新/变化事实按每页最多 32 条、目标 64 KB 打包（超目标的单个事实独占一页）。
3. 写入并读回校验全部新页。未变的封闭页复用，只合并有界尾页，避免每次 ACK 增加一个永久小页。
4. 所有引用准备成功后，单次同步替换活动检查点；随后才允许确认出队/发布内存态。
5. 提交后清理不再被引用的页；物理清理失败记录 cleanupPending，不推翻已提交检查点。

作答事实本身不可变，submitAttempt 共享历史对象并只复制数组与可变状态，避免每次克隆已确认历史。
同步恢复/确认中原有全量合并仍可能复制内存历史；本阶段不宣称全部 CPU 或内存成本已变成常量。

首次迁移准备因空间、写入或校验失败，若还没有尝试提交新格式，仍可用单次写保存**完整原格式**候选快照，
并返回 protocol:0 / migrationDeferred:true；本进程之后继续原格式，重启或仓储层 retryMigration 后再试。
这一退路不删流水、不丢待传项，也不把不完整分段当成成功恢复。已有分段格式遇到错误不降级，必须明确失败。

若已经尝试提交根检查点，API 报错也不能确定根未写入；保留新准备页供重启辨认实际根，不按失败删除可能
已被引用的页。错误仍报告失败，重试依靠原业务操作 ID。进程中断时要么旧根完整，要么新根及引用完整；
这里依赖微信同步单 key 存取 API 的正常替换语义，不等同于已验证设备断电/介质故障保证。

## 状态、清空、导出与回滚

store.getLocalStorageStatus() 返回 ready/read_error/write_error、error、protocol、migrationDeferred、cleanupPending。
不会返回题目、答案或身份令牌。写失败沿用 PERSIST_ATTEMPT_FAILED / PERSIST_ACK_FAILED 等现有失败语义。
匿名清空若检查点失败返回 PERSIST_CLEAR_FAILED；登录账号若删除意图已持久接受但本地重置尚未落盘，
保留既有恢复规则并返回 pendingLocalReset:true。clearScope 先作废旧内存/异步上下文，再提交空墓碑；失败不报完成。

清空/代次变更提交后清理旧页和备份。cleanupPending 表示物理清理尚未完成；不能把逻辑清空说成物理擦除。
尚未引用的准备页可能在中断/清理失败后占空间，后续成功检查点或作用域清理会再清理。

store.exportLocalSnapshot() 导出当前已落盘的完整领域快照，包含待传项；不会用第一份迁移备份替代最新状态。
store.rollbackLocalStorage() 只允许离线且无 dirty、拉取或在途任务时执行：先写最新完整 v3 根，成功后才清理分段。
写失败保留原分段引用；成功返回 restartRequired:true，须停止当前客户端后再切换代码，否则新活动可能再次分段。
不存在自动回滚；缺页时保留现场，需要核对本地待传项、云端事实和备份，不得直接覆盖为旧备份。

新物理格式不能由旧客户端读取。发布前必须协调应用版本与运行时 forceUpdate/minVersion（本代码版本 1.1.0），
且**同设备回退旧代码前必须先离线导出最新完整旧格式**。强制更新标记不能代替本地格式回滚。
本提交未调整真实运营配置，不部署、不迁移真实学习数据。

## 验证与剩余风险

故障注入覆盖备份/分段/根写失败、根已写后 API 报错、缺段/坏段、热缓存 key 丢失、作用域/代次篡改、
清理失败墓碑、确认丢失/重启、原待传操作与规范 ID 共存、回滚失败/最新状态导出、初次迁移延期。
现有双设备、账号切换、离线、清空、页面和管理员权限回归继续运行。

对比与原始样本见 docs/reports/learning-storage-segmented-2026-11-02.md。首次迁移仍有明显同步耗时和额外
备份/分段空间；容量不足时会延期，不能把正常空间的基线当成所有设备的保证。
AI/待传历史仍可能较大、冷加载仍读全部历史、恢复/确认仍有内存合并成本；去重原题、分段 AI、领域进一步
拆分、配额准入及可操作的损坏恢复界面继续跟踪 #11。真实微信配额、布局/错误呈现和设备中断验收未完成。
