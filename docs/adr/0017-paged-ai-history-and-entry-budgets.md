# ADR 0017：AI 历史分段与学习存储单项预算（Issue #11）

- 状态：Implemented，未部署；微信隔离环境验收未完成
- 前置：ADR 0015–0016；应用代码 1.2.0；学习领域快照和云同步协议不变

## 根因与范围

已确认作答分段后，AI 历史仍内联在活动根，普通作答还会克隆全部对话。
合成基线的 1 万作答 + 1 万 AI 消息，每次作答写约 5.02 MB。
本地 pushAiMessage 继续保留最近 60 条；同代次跨设备合并和旧快照可以更大，本次不修改这些业务保留/合并规则。

只改变本地物理存储：AI 消息分页、备份分块和写入预算。outbox、会话和统计仍留在活动根，不能为腾出空间删除未确认事实。
云端仍接收完整领域 AI 列表；本阶段没有降低网络负载或服务端文档大小，也没有对 outbox 分页。

## 格式与原子边界

| 内容 | 物理格式 | 读取与提交规则 |
| --- | --- | --- |
| 旧作答分段根 | version:4 / localRepository.version:1 | 继续读取；无 AI 升级时保持兼容 |
| 含 AI 分段的根 | version:5 / localRepository.version:2 | aiMessages 固定为空数组，元数据保存 aiEpoch、aiPages、aiCount |
| AI 页 | exam_quiz_ai_history_v1__scopeHash__contentHash | 内容绑定账号、dataEpoch、pendingDeleteId、aiEpoch 和有序完整消息 |
| 领域导出 | version:3 | 重建全部消息与待传项，不携带物理元数据 |

AI 页按最多 32 条、目标 64 KB 打包；单条超过目标时独占一页，但仍受单项预算限制。
仓储保持原始消息顺序及重复项，不按 time 或内容额外去重。多个相同页的引用可以重复，读取时也按引用顺序重复展开。
消息作为只读值复用；未变封闭前缀页不重写，变化尾页重新打包。窗口移位或中间编辑可能重组后续页，不宣称任意修改均为常量成本。

作答页和 AI 页使用独立签名缓存：确认作答不会因作答索引改变而重新读取全部 AI 页。
普通新答案共享只读消息对象，仅复制数组，不克隆整份对话。冷启动仍需校验完整 AI 历史，恢复/确认仍有全量内存和合并成本。

所有准备页及备份先写入并读回验证，最后单次提交根，之后才发布内存态/清理旧页。
缺页、坏页、账号/代次不符均明确失败，释放缓存并保留 readError；既有 v5 失败不能用内联空列表或旧备份降级。
根写入后 API 报错保留可能已引用的新页，并要求重启核对；预算拒绝发生在原生调用前，不标为结果不确定。
切号释放缓存，整体清空仍先提交墓碑；AI 清空/纪元变化后以新根为准，旧 AI 页只在提交后清理。
迁移档案可能保留迁移时的旧对话，绝不自动作为当前 AI 历史恢复；整体清空、dataEpoch 重置或成功回滚时再清理该档案。

## 单项与总容量预算

[腾讯官方同名 Storage API](https://intl.cloud.tencent.com/zh/document/product/1219/68028) 描述单 key 1 MB、总上限 10 MB；
实际总额度取运行时 getStorageInfoSync，不能用 Node 的可用内存代替微信配额。
每次学习仓储写入（活动根、页、备份、清空和回滚）先按 key + JSON 的 UTF-8 字节检查 **900 KiB** 工程预算，给原生编码/元数据留余量。
这是保守估算，不是对微信原生序列化和磁盘分配的精确测量。

准备任何新页前先检查完整候选根和所有准备项；活动根过大返回 LOCAL_ENTRY_TOO_LARGE，不先写一批注定不能提交的页。
迁移/新页准备沿用峰值准入与余量，每次原生写前再根据已知运行时总占用检查替换增长量，处理准入后空间变化。
总额度元数据不可用时，新分段准备延期；完整旧格式退路可尝试原生写入，结果仍以实际 API 为准，不假设容量无限。

旧格式首次迁移准备失败时，仅当完整 v3 候选能通过预算且原生写成功才报告已保存并延期。
健康 v4 的可选 AI 升级在提交根前失败，可重新准备完整 v4 检查点（AI 内联、作答页和待传项齐全）并延期；
后续本进程不在每次作答重复尝试升级，显式本地检查重试可再次尝试。
已有 v5、旧根不可读，或原生根结果不确定时没有这一退路。

待传队列/统计/会话或单条消息仍可能超过预算。此时作答返回 PERSIST_ATTEMPT_FAILED，原检查点和待传项不变；
不静默截断、不伪造确认、不把保存失败说成恢复完成。后台写失败保持 dirty 与可观察状态。
旧全局档案仍按旧领域版本先复制、再由 store 升级；复制若超限/失败，保留源 key 并阻止该账号初始化为空档案。
状态查询与订阅均呈现不可读保护，本地重试在源档案可完整保存后才解除；不会为通过预算截断旧输入。

## 大备份与回滚

小迁移档案继续保存完整旧对象；超出单项预算时，序列化 JSON 按最多 16,000 个 UTF-16 单元分块（避开代理对中点），
块有账号/内容摘要，manifest 绑定有序块摘要及总 UTF-8 长度。大摘要只对有界块/描述符计算，避免一次构造整档哈希字节数组。
v4 升级若无已有迁移档案，备份完整解码领域快照，避免保存会在后续清理中失效的旧物理页引用。
已有备份不会被当前写入覆盖。readMigrationBackup 只读校验档案，不用于自动恢复当前数据；损坏档案不影响健康当前根。
提交后只清理当前账号未引用的准备页/备份孤块；备份读取失败时保留现场并标记待清理。

exportLocalSnapshot 仍导出最新已提交的完整 v3 数据；rollbackLocalStorage 沿用离线且无待写/在途任务门禁。
回滚若完整 v3 根超过预算则明确失败，保留 v5 根和所有引用。大档案需要受控离线文件导出与后续恢复方案，不能直接安装旧代码。
旧 1.1.0 客户端不能读 v5，会明确拒绝；发布前须协调版本/运营配置，代码版本已为 1.2.0，本 PR 未修改真实配置。
