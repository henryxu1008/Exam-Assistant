# 判分协议升级与隔离验收（Issue #3 / #5）

当前阶段完成源码级合成验证，尚未部署云函数或通过真实 CloudBase / 微信验收。
所有案例只创建内存设备、内存数据库与合成题目；没有读取真实学习档案、运营配置或调用付费 AI。

## 可复现的源码组合

旧版本固定为 PR #20 合并后的 main：`1b0639d7adaea1e9ba1262a4bf0a5a737169af57`，应用 1.2.0，
内容树 `3ab21c693ed5721ce2a23af0fa24c25966fcee42`。当前候选应用为 1.3.0，判分协议见 ADR 0018。

在可信完整 Git checkout 中准备旧版本独立目录，再从当前目录执行：

```bash
git worktree add --detach ../Exam-Assistant-1.2.0 1b0639d7adaea1e9ba1262a4bf0a5a737169af57
npm run check:grading-upgrade -- --previous-dir ../Exam-Assistant-1.2.0
```

命令不自行拉取源码、不部署、不连接云，也不读入用户离线导出文件。它会执行所指定目录的程序，
因此 previous-dir 必须是核对过的可信 1.2.0 checkout。CI 分别检出候选和上述固定 SHA，运行同一命令。
旧客户端、旧共享依赖和旧服务端均从旧目录加载；没有把旧协议的返回值简单写成成功/失败替身。
两版本使用相同的合成题目输入，设备存储与数据库始终由测试替身隔离。

报告只输出场景结果、代码版本和原生未验收标志，不输出 token、答案、题目内容或学习档案。
场景断言失败返回非零，缺少可信基线时也失败，不以跳过代替通过。

| 场景 | 已验证结果 |
| --- | --- |
| 1.2.0 客户端 + 旧服务端 | 按旧协议确认一次；事实没有服务端判分证据 |
| 1.2.0 客户端 + 当前服务端 | 明确 QUESTION_PROTOCOL_REQUIRED，保留原队列、不创建事实 |
| 1.3.0 客户端 + 旧服务端 | 明确 QUESTION_PROTOCOL_REQUIRED，保留原队列、不创建事实 |
| 1.3.0 客户端 + 当前服务端 | 原发布归档判分、返回有效证据，事实与聚合只计一次 |
| 1.2.0 离线作答后升级客户端 | 1.3.0 按新协议发送原队列，业务答案、分数、用时与客户端时间不变 |
| 旧服务端已接受但丢 ACK 后升级 | 原事实确认并出队，不补造判分/接收时间，即使旧得分不正确也不重写 |
| 新服务端接受并丢 ACK 后切回旧后端 | 新客户端被明确拒绝并保留队列；恢复当前服务后确认原事实，不重计、不改首次接收时间 |
| 缺归档后补齐授权发布 | 首轮缺档保留原队列；显式准备匹配发布归档后下一轮补传成功 |

另有真实 store / studySync 故障测试覆盖：内容/配置错误首轮返回原始原因、不重复发送，
归档访问暂时失败继续重试，修复后新一轮允许恢复。修复前 GRADE_MISMATCH 可复现三次发送后返回
SYNC_RETRY_EXHAUSTED；当前首轮即返回 GRADE_MISMATCH，原队列与云端事实保持不变。

## 发布顺序与失败处置

1. 先核对隔离环境权限及当前队列涉及的发布归档。内置 Mock / 本地自签内容不代表已经发布；
   不自动把队列快照上传为题库，不删除队列，不通过改分或覆盖发布记录放行。
2. 在取得部署授权并完成原生验收后，协调当前 studySync 与 1.3.0 客户端上线。
   新旧版本混用期间会明确拒绝版本化写入，必须保留持久队列并提供客户端升级路径。
3. 内容/配置类错误先核对归档与原始事实；PUBLISHED_RELEASE_NOT_FOUND 须核对是否缺少合法历史发布。
   READ_RELEASE_FAILED 按访问故障排查，不能将超时当成无文档、补造默认发布或强制覆盖。
4. 已接受事实保持首次内容。旧已接受事实仍未验证，不以当前题库追溯补分或补时间。
5. 后端回滚兼容测试只证明新客户端能保留队列并在前滚后恢复。旧后端仍能接受旧客户端上报分数，
   因此不能据此允许旧后端继续承接写入。回滚方案须先确定实际停写/升级安排，不承诺一键无损回滚。

剩余事项：原生验收、缺档/历史冲突的专用处置入口，以及 #3 的完整领域迁移和 #5 的内容治理后续。
本指南未授权部署、修改云权限或真实配置。
